## Why the dataset was invalidated

In sequence 14, an accepted GLM candidate did not compile. Maven correctly
returned a non-zero compilation failure, but no Surefire XML could exist
because JUnit never started. The pre-correction harness interpreted the
missing JUnit evidence as `INFRASTRUCTURE_ERROR` and terminated the run.
That causal classification was wrong: production code generated by the
model caused the compilation failure.

RepoSuture now keeps a baseline compilation failure classified as
infrastructure, while an accepted-candidate compilation failure is recorded
as `COMPILATION_FAILED`. In full-agent mode it rolls back the candidate,
returns bounded compilation evidence to the Agent, and permits replanning.
If the run remains unresolved, its primary cause is `TARGET_UNRESOLVED`,
not infrastructure. Real Maven/JUnit regression tests cover both rollback
and a later successful candidate.

The task policy requires all observations in one comparison to use one
source commit. Restarting the required 28 repair attempts and 12 ablation
attempts after the 15 assignments already made would total 55 assignments,
exceeding the hard cap of 40. RepoSuture therefore issued no further paid
request. A fresh evaluation budget is required for a valid Release 0.4
comparison.
